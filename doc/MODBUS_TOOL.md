# modbus_tool — обслуживание одной процессорной платы

Утилита для работы с одной платой по карте регистров v2 ([MODBUS_MAP_v2.md](MODBUS_MAP_v2.md)).
Операции реализованы в `BoardClient` (`include/modbus/board_client.h`) — тот же класс
будет использовать опрос плат в SlowControl.

```
modbus_tool [-b 38400] [-t 500] <device> <address> <команда> [аргументы]
```

| Команда | Что делает | Пишет в плату |
|---|---|---|
| `info` | состояние (input 0–27), настройки (holding 0–100), CPU ID, ID термометров, сверка DAC | нет |
| `read input\|holding <start> [count]` | сырые регистры | нет |
| `watch [сек]` | счётчик обновлений: период цикла, «не завис ли» | нет |
| `dac` | DAC: уставка (holding 0–95) против применённого (input 150–245) | нет |
| `sp-dump [backup.json]` | scratchpad: контрольная сумма, поля; с файлом — резервная копия | нет |
| `write <reg> <v>[,v...]` | holding-регистр(ы), значения десятичные или `0x...` | да |
| `dac-set <канал\|all> <v>` | DAC и проверка обратным чтением через два цикла платы | да |
| `hv-enable <маска>` | holding 96 | да |
| `sp-save` | стереть (103) и сохранить (105) scratchpad, прочитать и проверить | да, flash |
| `sp-load` | загрузить рабочие регистры из scratchpad (101) | да |
| `sp-erase` | только стереть scratchpad (103) | да, flash |
| `restore <backup.json>` | вернуть DAC, HV enable, gain/trip, задержку из копии и сохранить | да, flash |
| `set-address <новый>` | назначить адрес плате на заводском 247 | да, flash |

Порт на macOS — `/dev/cu.usbserial-*` (не `/dev/tty.*`: тот ждёт сигнал DCD).

## Без железа

```bash
python3 tests/fake_modbus_slave.py --address 1 --state /tmp/board.json   # печатает /dev/pts/N или /dev/ttysNNN
./modbus_tool /dev/pts/N 1 info
```
Перезапуск имитатора с тем же `--state` — это «перезагрузка платы».

## Проверка на плате — по шагам

Сначала только чтение; запись — после резервной копии.

1. `modbus_scanner -q -s 1 -e 247 <порт>` — найти адрес платы (247 = заводской).
2. `modbus_tool <порт> <адрес> info` — вся карта читается без исключений Modbus.
3. `modbus_tool <порт> <адрес> watch 10` — период цикла; сравнить с `cycle delay (99)`.
4. `modbus_tool <порт> <адрес> sp-dump backup_<адрес>.json` — **резервная копия**, контрольная сумма.
5. `modbus_tool <порт> <адрес> dac` — уставки совпадают с применёнными.
6. `modbus_tool <порт> <адрес> dac-set 0 <значение>` — запись DAC с обратным чтением; затем вернуть старое значение.
7. `modbus_tool <порт> <адрес> sp-save`, затем `sp-dump` — сохранение, контрольная сумма 0xAA55.
8. Перезагрузить плату (питание), `dac` — значения пережили перезагрузку (загружаются ли они сами — вопрос к Игорю).
9. Смена адреса (по желанию): `sp-erase` → перезагрузить → плата на 247 → `set-address <новый>` →
   при необходимости перезагрузить → `restore backup_<адрес>.json` по новому адресу.

## Что не подтверждено прошивкой (вопросы к Игорю)

- Выполняется ли команда CSR в ближайшем цикле платы и отвечает ли плата во время записи во flash
  (утилита ждёт смены счётчика и повторяет запросы до 5 с).
- Начинает ли новый адрес действовать сразу после сохранения или только после перезагрузки
  (утилита проверяет оба варианта).
- Порядок слов в ID термометров и CPU ID (утилита печатает старшее слово первым).
- Раскладка битов holding 97 (утилита показывает сырое значение).
